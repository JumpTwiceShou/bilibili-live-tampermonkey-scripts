# 直播间布局改造需求整理

## 1. 目标

围绕 [https://live.bilibili.com/31294374](https://live.bilibili.com/31294374) 所反映的问题，整理一版适用于通用脚本的需求规格。目标不是只修单个房间，而是覆盖普通直播间与同类特殊 layout 直播间。

## 2. 适用范围

### 2.1 普通直播间页面

- 适用示例：`32031523` 及同类标准直播间。

### 2.2 特殊 layout 直播间页面

- 适用示例：`6524090`、`35`、`794677`、`732` 及同类活动页 / 会场页。
- 脚本必须基于页面结构或布局特征自动识别，不允许按房间号硬编码。

## 3. 通用原则

- 实现目标是做通用脚本，不依赖某个固定房间。
- 允许使用本地 `kounan profile` 登录态调试，但最终产物不能依赖该 profile 才能工作。
- 特殊页面的调整不能只是对播放器做整体 `scale` 放大，而要按普通直播间的布局思路进行重排。
- 优先复用官方素材、官方 CSS、官方 DOM 结构、官方接口，避免完全手搓一套外观相似但行为不一致的假 UI。
- 特殊页面不得通过加载 `32031523` 页面或桥接另一个直播间 `iframe` 的方式实现侧栏或关注弹层。

## 4. 功能需求

### 4.1 普通直播间礼物大面板

- 打开礼物大面板时，不得挤占视频画面，不得导致视频缩小。
- 礼物大面板应覆盖在视频画面上显示。
- 礼物大面板固定高度，默认只展示约两行礼物。
- 礼物列表超出部分在面板内部滚动。
- 礼物大面板显示在右下角，不显示在右上角。

### 4.2 特殊 layout 页面整体布局

- 特殊页面播放器布局应尽量参考普通直播间，至少对齐以下维度：
  1. 主视频区域的宽度与比例。
  2. 右侧弹幕区宽度。
  3. 底部礼物区的显示尺寸、礼物个数、排布方式。
- 播放器区域应通过重排容器尺寸、位置、分栏关系来实现放大，而不是简单整体缩放。

### 4.3 特殊 layout 页面：保留列表版本

- 顶部 / 上方 `list` 区域保留。
- `list` 区域保持默认大小，不跟随播放器放大。
- 仅放大视频区域。
- 页面默认进入时，`list` 自动处于收起状态。
- 收起箭头需与第一行内容保持同一水平线。
- `list` 收起后，播放器区域需向上贴合，不能留下明显空白。

### 4.4 特殊 layout 页面：no-list 版本

- 直接隐藏顶部 `list` 区域。
- 播放器保持放大后的布局。
- 同样不能采用单纯整体缩放，而要按普通直播间结构重排。

### 4.5 特殊页面右侧侧栏

- 特殊页面需具备与普通直播间相似的右侧侧栏。
- 侧栏应尽量复用普通直播间的 UI 和实现方式。
- 侧栏位置应与普通直播间一致：位于页面右侧、整体偏下、不可漂移到页面中部。
- 侧栏白色背景容器的以下样式应尽量与普通直播间一致：
  1. 宽度。
  2. 高度。
  3. 圆角。
  4. 阴影。
  5. 内边距。
  6. 按钮尺寸。
- “实验室 / 关注”按钮本体不得变窄，不得压缩文字。
- “关注”弹层展开时，左侧内容不得被裁切。
- 普通直播间下滑后会出现“返回顶部”按钮，特殊页面需具备同样的出现逻辑和位置。
- 特殊页面点击“返回顶部”时，滚动目标不是整个页面最顶，而是播放器所在区域顶部。

### 4.6 “关注”弹层的数据与交互

- 弹层中的直播间卡片必须是可点击跳转的真实超链接。
- 数据与交互必须来自当前页面可用的官方能力，不允许通过引入 `32031523` 页面来桥接侧栏数据。
- 实现过程中不能带出 `32031523` 的声音。
- 不允许通过“桥接另一个直播间 iframe”的方式实现关注弹层。

## 5. 实现约束

### 5.1 页面识别

- 必须识别“普通直播间”和“特殊 layout 页面”两类页面。
- 特殊页面识别依据应来自 DOM 结构、容器布局、页面标记或稳定特征，而非房间号名单。

### 5.2 布局实现

- 禁止仅通过整体 `transform: scale(...)` 放大播放器容器来交付需求。
- 应分别处理主视频区、弹幕区、礼物区、上方 list 区、右侧侧栏等模块。

### 5.3 资源与接口复用

- 优先使用官方已有 DOM、样式、图标、接口、组件结构。
- 如需补齐缺失结构，需保证交互、尺寸、位置与普通直播间尽量一致。

## 6. 验收标准

### 6.1 普通直播间验收

- 在标准直播间打开礼物大面板后，视频尺寸不变。
- 礼物大面板覆盖在视频区域右下角。
- 面板固定高度，仅显示约两行礼物，超出后内部滚动。

### 6.2 特殊 layout 页面验收

- 同类活动页 / 会场页可被脚本自动识别，无需单独加房间号。
- 播放器布局接近普通直播间，不是单纯整体拉伸或缩放。
- 右侧弹幕区、底部礼物区、视频区比例符合普通直播间视觉预期。

### 6.3 保留列表版本验收

- 默认进入页面时，顶部 `list` 已收起。
- 收起箭头与第一行对齐。
- 收起后播放器向上贴合，没有大面积空白。
- `list` 本身尺寸维持默认，不跟随视频放大。

### 6.4 no-list 版本验收

- 顶部 `list` 不显示。
- 播放器维持放大后的重排布局。

### 6.5 侧栏与关注弹层验收

- 特殊页面存在与普通直播间一致风格的右侧侧栏。
- 侧栏位置、容器尺寸、圆角、阴影、按钮尺寸基本一致。
- “实验室 / 关注”按钮宽度正常，文字不被压缩。
- “关注”弹层展开后不裁切左侧内容。
- 弹层中的直播间卡片可真实点击跳转。
- 页面下滑后会出现“返回顶部”，点击后回到播放器区域顶部而非页面最顶。

## 7. 建议测试样例

- 普通直播间：`32031523`
- 特殊 layout：`6524090`
- 特殊 layout：`35`
- 特殊 layout：`794677`
- 特殊 layout：`732`

以上样例用于验证“同类页面均可生效”，不是用于房间号硬编码。
